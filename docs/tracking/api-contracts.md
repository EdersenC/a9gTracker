# Tracking API and Realtime Contracts

## Versioning and Base Rules
- API namespace: `/api/v1/tracking`
- Content type: `application/json`
- Time format: RFC3339/ISO8601 UTC (`YYYY-MM-DDTHH:MM:SS.sssZ`)
- Numeric precision:
  - `lat`, `lon`: up to 6 decimal places
  - `speedKph`, `headingDeg`, `accuracyM`: up to 2 decimal places

## Auth Assumption
Tracker requests are authenticated with shared-secret HMAC headers.

Required headers for ingest:
- `X-Tracker-Id`: tracker identifier (must match body `trackerId`)
- `X-Timestamp`: unix epoch seconds generated by tracker
- `X-Signature`: `hex(hmac_sha256(secret, canonical_string))`

Canonical string:
`<trackerId>.<X-Timestamp>.<raw_request_body>`

Validation rules:
- Missing/invalid signature -> `401 UNAUTHORIZED`
- Timestamp skew > 300s -> `401 UNAUTHORIZED`
- Unknown trackerId -> `403 FORBIDDEN`

## 1) Ingest Endpoint
`POST /api/v1/tracking/ingest`

Request body:
```json
{
  "trackerId": "truck-17",
  "timestamp": "2026-05-09T13:25:44.000Z",
  "lat": 40.712776,
  "lon": -74.005974,
  "speedKph": 52.4,
  "headingDeg": 183.2,
  "accuracyM": 7.5
}
```

Required fields:
- `trackerId` (string, 1..64, `[A-Za-z0-9._-]+`)
- `timestamp` (ISO8601 UTC)
- `lat` (number, `-90 <= lat <= 90`)
- `lon` (number, `-180 <= lon <= 180`)

Optional fields:
- `speedKph` (number, `0 <= speedKph <= 400`)
- `headingDeg` (number, `0 <= headingDeg < 360`)
- `accuracyM` (number, `0 <= accuracyM <= 10000`)

Success response `202 Accepted`:
```json
{
  "ok": true,
  "eventId": "evt_01JTX4J8J4Q4G1",
  "ingestedAt": "2026-05-09T13:25:44.210Z"
}
```

Idempotency behavior:
- Duplicate event key `(trackerId, timestamp)` should not create duplicate history points.
- Duplicate ingest returns `202` with same/linked `eventId`.

## 2) Latest Positions Endpoint
`GET /api/v1/tracking/latest`

Query params:
- `trackerIds` (optional CSV list, max 200 IDs)

Success response `200 OK`:
```json
{
  "items": [
    {
      "trackerId": "truck-17",
      "timestamp": "2026-05-09T13:25:44.000Z",
      "lat": 40.712776,
      "lon": -74.005974,
      "speedKph": 52.4,
      "headingDeg": 183.2,
      "accuracyM": 7.5,
      "receivedAt": "2026-05-09T13:25:44.210Z"
    }
  ]
}
```

## 3) History Query Endpoint
`GET /api/v1/tracking/history`

Query params:
- `trackerId` (required)
- `from` (required, ISO8601 UTC)
- `to` (required, ISO8601 UTC)
- `limit` (optional, default `1000`, max `10000`)
- `order` (optional: `asc` or `desc`, default `asc`)

Validation:
- `from <= to`
- `to - from <= 7 days` (contractual upper bound to protect service)

Success response `200 OK`:
```json
{
  "trackerId": "truck-17",
  "from": "2026-05-09T12:00:00.000Z",
  "to": "2026-05-09T14:00:00.000Z",
  "items": [
    {
      "timestamp": "2026-05-09T13:25:44.000Z",
      "lat": 40.712776,
      "lon": -74.005974,
      "speedKph": 52.4,
      "headingDeg": 183.2,
      "accuracyM": 7.5,
      "receivedAt": "2026-05-09T13:25:44.210Z"
    }
  ],
  "nextCursor": null
}
```

## 4) Realtime Channel Contract
Primary channel: WebSocket
- URL: `/api/v1/tracking/stream`
- Auth: bearer token or session (frontend scope), not tracker HMAC

Subscription message from client:
```json
{
  "type": "subscribe",
  "trackerIds": ["truck-17", "truck-22"]
}
```

Server event message:
```json
{
  "type": "position.updated",
  "eventId": "evt_01JTX4J8J4Q4G1",
  "data": {
    "trackerId": "truck-17",
    "timestamp": "2026-05-09T13:25:44.000Z",
    "lat": 40.712776,
    "lon": -74.005974,
    "speedKph": 52.4,
    "headingDeg": 183.2,
    "accuracyM": 7.5,
    "receivedAt": "2026-05-09T13:25:44.210Z"
  }
}
```

SSE fallback:
- Endpoint: `GET /api/v1/tracking/stream/sse`
- Event name: `position.updated`
- Data payload equals WebSocket `data` object.

## Error Model (All HTTP Endpoints)
Format:
```json
{
  "ok": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "lat must be between -90 and 90",
    "details": {
      "field": "lat"
    }
  }
}
```

Error codes:
- `VALIDATION_ERROR` -> `400`
- `UNAUTHORIZED` -> `401`
- `FORBIDDEN` -> `403`
- `NOT_FOUND` -> `404`
- `RATE_LIMITED` -> `429`
- `INTERNAL_ERROR` -> `500`

## Rate and Reliability Expectations
- Ingest endpoint must tolerate tracker retries and intermittent duplicate delivery.
- Suggested baseline limits:
  - per tracker: 1 request/sec sustained, bursts up to 10.
  - global protection via `429` responses.
- Realtime delivery is at-least-once; consumers should de-duplicate by `eventId`.
